# Maintenance runbooks

Every recipe below was run at least once during the project; dates and commits are given so
you can look at the real history (`git log`) when something differs.

## 0. Local setup from nothing

    git clone git@github.com:emilyriehl/VerboseReintroductionToProofs.git
    cd VerboseReintroductionToProofs
    git remote add upstream https://github.com/emilyriehl/ReintroductionToProofs
    # Lean: elan picks the toolchain from lean-toolchain (v4.31.0)
    lake exe cache get      # Mathlib binaries; without it Mathlib compiles for hours
    lake build              # ~10 min the first time, ~2 min afterwards

`lake build` runs `MakeGame` (in `Game.lean`) which writes the game data the server needs to
`.lake/gamedata/` and regenerates the translation template `.i18n/en/Game.pot`. Warnings from
`MakeGame` about inventory items ("no world introducing …") are real problems: see §6.

Dev server (lean4game v4.31.0 client + relay):

    cd ..
    git clone https://github.com/leanprover-community/lean4game
    cd lean4game && git checkout v4.31.0
    git am ../VerboseReintroductionToProofs/docs/handoff/lean4game-local-fixes.patch   # optional, see §7
    npm install
    npm start               # relay on :8080, client on :3000
    # open http://localhost:3000/#/g/local/VerboseReintroductionToProofs

The dev server reads the game from a sibling folder named after the game (the URL's last
segment). After `lake build` reload the browser; the relay does not need a restart. If a stale
relay holds port 8080 after a crash, find it with `ss -ltnp 'sport = :8080'` and kill that pid.

Browser playthrough harness: `scripts/ux-tests/README.md`.

## 1. Syncing with the original game

**Automatic.** `.github/workflows/sync-upstream.yml` runs Mondays 05:17 UTC (and on demand from
the Actions tab). When the original's `main` has commits not yet merged here it merges them on a
branch `sync/upstream-<sha>`, keeps this repository's `lean-toolchain`, `lakefile.lean` and
`lake-manifest.json`, advances `UPSTREAM_COMMIT`, pushes the branch and opens a pull request. If
the merge has conflicts the commit contains the conflict markers and the PR says so. If GitHub
refuses to let the workflow open a PR (repository setting *Allow GitHub Actions to create and
approve pull requests*, off as of 2026-11-11) it opens an issue instead. Either way a human
finishes the job with the manual recipe.

**Manual recipe** (used on 2026-10-30 and 2026-11-11):

    git fetch upstream
    git merge --no-ff --no-commit upstream/main
    git diff --name-only --diff-filter=U            # conflicts
    # Resolve. Policy:
    #  - level files: keep this edition's text ("ours") whenever it already contains the upstream
    #    edit in Verbose wording; otherwise port the upstream edit by hand (proof lines become
    #    Verbose sentences, hints name sentences instead of tactics)
    #  - Game.lean, .i18n/en/Game.pot, LICENSE: ours (Game.pot is regenerated by the build anyway)
    #  - lean-toolchain, lakefile.lean, lake-manifest.json: always ours
    git checkout --ours -- <files that keep our text> && git add <them>
    git rev-parse upstream/main > UPSTREAM_COMMIT && git add UPSTREAM_COMMIT
    lake build                                       # must pass; regenerates Game.pot
    git add .i18n/en/Game.pot
    python3 scripts/run_level.py . <World> <n> tests/replays/<X><n>.txt   # every level whose file changed
    python3 scripts/check_parity.py ../ReintroductionToProofs . --allowlist parity-allowlist.txt
    git diff --cached <previous main>                 # read it all
    git commit && git push origin main
    # then re-import on adam (§4)

`check_parity.py` needs a checkout of the original at `UPSTREAM_COMMIT` (any path; the
workflow clones one). Warnings about statement docstrings are expected (this edition's docstrings
mention sentences); errors mean a statement, level list or world graph differs and must be fixed
or, for a deliberate difference, listed in `parity-allowlist.txt`.

What to expect in conflicts: upstream touched 159 proofs' worth of hints and introductions in
PR #47 (prose pass), and this edition had mirrored them (PR #1 here) before the merge arrived;
all 16 conflicts resolved as "ours". The cross-link paragraphs in `Game.lean` (#50 upstream)
conflict with this edition's own paragraphs every time that region changes; keep ours.

## 2. Regenerating `Game.pot`

`lake build` does it (lean-i18n runs inside `MakeGame`). Commit the result with the change that
caused it; only the `POT-Creation-Date` header changes when no text changed, and that is fine to
commit or drop.

For the **original** game the same holds, but it is on Lean v4.23.0 and Emily's working copy
must not be touched. To regenerate its `Game.pot` for a PR without building Mathlib: in the
separate PR clone, copy her finished build (`rsync -a --delete ~/Math/Formalization/ReintroductionToProofs/.lake/ ./.lake/`,
then delete `.lake/lakefile.olean*`) and run `lake build` there (about one minute: it rebuilds
only changed level modules and `Game`). Used for PR #50. Check the result by comparing msgid
sets ignoring order, not by reading the raw diff (entries move around).

## 3. Replaying levels (the regression suite)

`tests/replays/*.txt` are 253 recorded player inputs, at least one per level plus variants,
named `<letter><level>[variant].txt`; the letter→world table is in `scripts/replay_all.py`
(T Type, F Function, I Implication, P Product, K Conjunction, C Coproduct, D Disjunction,
E Empty, N Negation, L Classical, Q Equality, B Boolean, U Quantifier, A AdvancedFunction,
V Equivalence, M NaturalNumbers, W Dependent). Files `H_*` and `*_help*` end with `help` and are
for reading the help output, not pass/fail; `*_wrong*` files are inputs the game must reject.

    python3 scripts/run_level.py . ProductWorld 3 tests/replays/P3.txt      # one level, prints diagnostics
    python3 scripts/replay_all.py                                            # everything, serial, ~45 min
    python3 scripts/replay_all.py --worlds NaturalNumbersWorld,DependentWorld

`run_level.py` builds the same document the relay sends to Lean (`Runner "…" "<World>" <n>
(difficulty := 2) (inventory := [...]) := by …`) and runs `lake env lean` on it, so it exercises
the inventory check exactly as the website does (difficulty 2 = "regular": unknown words are
errors). It needs a finished `lake build`. Output documents land in `.lake/runner-out/`.

When you change a level's proof, update or add its replay file. When you add a sentence, add a
replay that uses it in the level that teaches it.

## 5. Changing or adding a level

Level files are `Game/Levels/<World>/L<nn>_<Name>.lean`, listed in `Game/Levels/<World>.lean`;
the world graph is in `Game.lean`. The mathematics (`Statement`) is shared with the original:
change it there first, let it sync, then adapt here. Checklist for a change here:

- Proof lines are Verbose sentences; every rewrite ends with an explicit `We conclude by rfl`
  (this edition's `We rewrite using` never closes goals, like the original's `rw`).
- Hints name sentences, not tactics, and may use `{p}` placeholders for the player's names.
  A hint's goal must match literally (Verbose's `⇒` display included). Hidden hints
  (`Hint (hidden := true)`) show only on request.
- Every new *word* a player types that is alphabetic must be in the inventory, or difficulty 2
  rejects it: for a new sentence add `NewHiddenTactic «word» …` for its words and a
  `TacticDoc «word»` for at least the leading word (a hidden word without any doc never
  reaches the inventory). Words that are also Lean keywords or tactics are written `«apply»`.
  Capitalised types used as words (`Prop`, `Type`) are declared the same way.
- Teach the sentence in `GameHelp.taughtAt` (`Game/Metadata/Tactic/Help.lean`) so `help` offers
  it from that level on and not before. `help` reads the world graph from
  `.lake/gamedata/game.json`, so a changed graph needs a rebuild.
- Sentences that would trivialise a later level are switched off there with
  `DisabledTactic «word»` (e.g. `«compute»` in Natural Numbers World 7–10).
- Replay file in `tests/replays`, `lake build` clean, `check_parity.py` clean.

## 6. Reading `MakeGame` warnings

- "No world introducing X": a word used in a sample proof is not declared anywhere. Either add
  it to the level's `NewTactic`/`NewHiddenTactic`/`NewTheorem`, or write the proof with a name
  that is declared (this is why the proofs say `Nat.zero_add`, `Eq.symm`, `Nat.pred_comp_succ`:
  with Mathlib in scope the short names resolve to Mathlib's root lemmas).
- "dependency loop": a word is introduced in a world that depends on a world using it. Move the
  `NewDefinition`/`NewTactic` to the earliest world that types the word (this happened with
  `False`, now in Negation World 1).
- Build errors `unknown parser location` or similar in `Overrides.lean`: the file opens
  `Lean.Parser.Tactic` inside a section for Verbose's `location`/`rwRuleSeq` syntax.

## 7. The lean4game client fork

Branch `local-fixes` of the lean4game clone (`~/Math/Formalization/verbose-game-spike/lean4game`,
based on tag v4.31.0; nine commits, 8 files, +117/−17) is also stored here as
`docs/handoff/lean4game-local-fixes.patch`. It fixes the local dev experience: world unlock, no
"Crashed!/Level not found" on world changes, correct completion detection, period stripping,
error text in the banner, a `proof state summary` console log. See `roadmap.md` §2 for what each
commit is and what should be upstreamed. adam runs the stock client, so players there have none
of this; its older client generation does not show the two serious bugs.

To use it: `git checkout v4.31.0 && git am docs/handoff/lean4game-local-fixes.patch` in a
lean4game clone, then `npm install && npm start`. To work on it further, rebase onto the lean4game
tag that matches `lean-toolchain` here.

## 10. Known failure signatures

| Symptom | Cause | Fix |
|---|---|---|
| Player's correct sentence rejected: "tactic `X` not available" | word missing from inventory, or hidden word without a `TacticDoc` | §5 |
| `help` suggests a sentence the player has not learned | `taughtAt` table incomplete | `Help.lean` |
| "Crashed!" banner / "Level not found" after moving to a new world (local dev) | per-world document folders in the stock client | client patch §7; reload the page as a workaround |
| World stays locked at "regular" after completing its prerequisites (local dev) | stock client checks the wrong world | client patch §7 |
| Every level crashes while someone is playing locally | `lake build` ran during the session | rebuild only when nobody plays |
| `We rewrite using h` closes the goal in Verbose but a trailing `We conclude by rfl` then errors | not in this edition (override removes the auto-`rfl`); appears if the override is lost | `Overrides.lean` |
| `By h we get x such that (h1 : P) and (h2 : Q)` silently produces `sorry` | ambiguity between the game's nameless synonym and Verbose's form | synonym declared `(priority := low)` in `Synonyms.lean` |
| Case goals show hypotheses from before the case split | goal blocker created outside the goal's context | `blockGoal` uses `g.withContext` in `Cases.lean` |
| `lake build` says `'gameExt' has already been used` | Verbose dependency does not have the rename | lakefile must point at the `lean4game-compat` branch (or a Verbose release containing the rename) |
| Weekly sync run fails at the last step | workflow may not create PRs | enable the repository setting, or use the issue it opened |
